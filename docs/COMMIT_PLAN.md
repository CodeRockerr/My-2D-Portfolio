## Manual staging workflow

These commands are examples for you to run; the assistant has not executed them.

For dedicated files:

```sh
git add path/to/file
git diff --cached
git commit -m "the chosen commit message"
```

New shared files must first be made available for partial staging:

```sh
git add -N vite-project/src/content.js vite-project/src/render.js vite-project/src/game.js vite-project/src/game-render.js vite-project/src/game-world.js vite-project/src/styles.css vite-project/src/game.css vite-project/src/studio.js
```

Then use `git add -p path/to/file` or your editor's selected-range staging. A newly added file may appear as one large hunk; use manual patch editing when Git cannot split it. Include corresponding imports, declarations, registrations and call sites. Review the actual staged content, not just the filename list.

Check the final assembled application with:

```sh
npm test
npm --prefix vite-project run format:check
npm run build
npm run test:browser
```

These commands test the working tree. If splitting features into independently buildable commits, also validate each staged snapshot in an isolated checkout; an otherwise complete working tree can hide missing staged dependencies.
